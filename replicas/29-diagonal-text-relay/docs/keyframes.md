# 斜向窗口：逐帧轨迹与锁定

坐标采用 960×540 逻辑画布，最终输出 1920×1080 / 30fps。`docs/frames/f0000.jpg` 就是源帧 0，完整提取 51 帧。

真实机制：一条斜向窗口整体向右扫描，依次揭示三个原本固定的字。不是三条独立条带，也不是三个字飞入。窗口内的画面铺满 540px；窗口外图像位于 y=54..486。窗口底部比顶部左移约 218px，宽约 354px。几何测量与追踪层见 `measurements.json`、`trace-contact.jpg`、`Trace` composition。

## 可编辑边界

`props.json` 提供三个字、起止图像、颜色、窗口宽度/斜率、时长与背景模式。所有位移按 `useCurrentFrame` 驱动；改变时长时将整段均匀映射到源帧 0..50。示例变体换成“看 / 懂 / 了”，换两张独立几何 SVG 图像，时长 2.5 秒，窗口宽 390。默认的 `product-camera` 近似层专用于参考素材；换普通图片时用 `crossfade`。

## 明确近似

- 电池里的流动、三维车体转动和物理摄像机拉远没有逐帧复刻；默认由静帧的几何变化近似。
- 宋体为本机可用的 Songti SC 导出字体，非原视频字体确认；阴影与遮罩边缘存在细微差异。
- 首轮颜色以解码帧为参考，未与原作者显示端色卡核对，不宣称显示端色彩一致。
- 不使用原参考整幅视频或源帧序列充当动画。`public/__reference.mp4` 仅供 Trace，公开打包时必须排除。
